# Данные первого запуска

`initial-prices.csv` — снимок недельных цен `ROSSTAT_PFO_WEEKLY / OPEN_DATA`,
выгруженный из рабочей БД. В каждой строке сохранены дата наблюдения и ссылка
на публикацию; это исторические данные, а не текущие цены.

Снимок от 18.10.2026: 1 372 цены, 14 регионов ПФО, АИ-92 и дизель,
49 недель наблюдений с 20.10.2025 по 12.10.2026.

После запуска локальной БД обновить снимок из корня проекта:

```powershell
pwsh -File scripts/export-initial-data.ps1
```

Скрипт только читает PostgreSQL сервиса `db` текущего Docker Compose.
Для другого контейнера: `-Container <имя>`. Выгружаются все недельные цены
источника Росстата; данные пользователей, пароли, журнал и внутренние ID
в файл не включаются. Пустая выборка или ошибка не перезаписывают CSV.

CSV входит в JAR и Docker-образ. При обычном запуске после миграций приложение
загружает его через существующий CSV-импорт, только если таблица цен пуста.
Успех отмечается в журнале `import_run` и сообщением
`INITIAL_DATA_IMPORT_SUCCESS` в логах. Повторный запуск пропускает загрузку;
если в БД уже есть любые цены, снимок ничего не добавляет и не исправляет.
Ошибка чтения или проверки CSV прерывает запуск, ошибочные строки не сохраняются.

Отключение при прямом запуске: `SERVICEOIL_SEED_ENABLED=false` или
`--serviceoil.seed.enabled=false`. Явный импорт через `import.file` также
отключает автозагрузку снимка. Другой CSV можно указать параметром
`--serviceoil.seed.file=file:/absolute/path/prices.csv`; он должен содержать
данные того же источника и иметь тот же формат.

## Проверка 18.10.2026

Собран отдельный образ `serviceoil-csv-check:local`. PostgreSQL 18.6 запущена
в отдельной сети `serviceoil-csv-check`, с `tmpfs`, без рабочего тома и порта БД.

- На пустой БД автоматически появились 1 372 цены и одна запись `SUCCESS`,
  `row_count=1372`, `rejected_count=0`.
- Повторная выгрузка из тестовой БД побайтно совпала с исходным CSV (SHA-256).
- При повторном старте осталось 1 372 цены и одна запись импорта.
  Отдельно изменённая в тесте цена сохранилась после следующего старта.
- Каталог и история через настоящий HTTP API: Postman, 5 проверок прошли;
  проверены покрытие, режим источника, дата, цена и ссылка первой строки CSV.
- CSV с одной корректной и одной ошибочной строкой: процесс завершился с кодом 1,
  цены и источник не записались, в журнале одна запись `FAILED`.
- При `SERVICEOIL_SEED_ENABLED=false` приложение запустилось с пустой таблицей цен.
- При явном `import.file` загрузились только 12 строк тестового `CONTRACT_WEEKLY`;
  автоматическая загрузка Росстата не выполнялась.
- Существующие `JpaImportTests`, `JpaMappingTests`, `JpaReadingTests`:
  H2 и PostgreSQL — по 21 тесту, 0 ошибок, 0 падений, 2 пропуска
  (проверки, включаемые отдельными системными свойствами).
